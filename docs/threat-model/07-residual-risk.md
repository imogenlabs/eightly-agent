# Residual Risk Register

What the gauntlet did **not** eliminate, and why it is accepted or deferred. Each
row notes the compensating control that keeps the residual risk tolerable. These
are the **[RESIDUAL]** leaves from `05-attack-trees.md`.

| Risk | Why accepted/deferred | Owner decision | Compensating controls |
|------|----------------------|----------------|----------------------|
| **Agent process holds Docker-socket access** | The agent's purpose is to broker the Docker API; the *process* talking to the socket is inherent and cannot be sandboxed away without removing the product. This is a property of the agent's own runtime, **not** a path the remote caller can ride. | ACCEPTED (design invariant) | Run the agent as a non-root user under systemd hardening (`NoNewPrivileges`, `ProtectSystem`, restricted syscalls) so a compromise of the agent process is contained. Note: mounting `docker.sock:ro` is **near-cosmetic** — the read-only flag only marks the socket file, not the API; a writer can still issue create/start over a "read-only" socket. It is not a real control and should not be relied on. |
| **Remote-caller escape via the proxy: what the allow-list still admits** | The proxy (`internal/proxy`) is an allow-list: only the method + path pairs in `routes.go` pass. Bodies of create, update, exec, volume and network create are parsed and refused if they ask for host reach (privileged; host or `container:` namespaces; capabilities beyond Docker's default set; host paths outside `--allowed-bind-roots`, which is empty by default, or Windows drive and UNC forms; `VolumesFrom`; devices, device requests, cgroup rules; other runtimes; annotations; sandbox overrides), and a body with a key twice (any case) is refused. Named volumes are inspected and held to the bind rule; the agent's own volumes and files are off limits. Exec, attach, archive upload, exec start and the WebSocket bridges inspect the target container and refuse the agent's own and any container that reaches the host; an unknown target is answered 404, and every checked call is forwarded by the inspected ID. What remains: (1) **symlinks under a bind root** — a container that can write under a root can plant a link, and the kernel follows it when a later bind of that path, or a local volume bound to it, is mounted. The agent refuses a mount through a symlink at create and again at start and restart: on the host for every root, in a container for every root mounted into it at the same path (container installs mount each root there, read-only). For a root a containerized agent cannot see it checks nothing, and refuses restart policies on containers that mount under it, so the daemon never mounts those on its own. What remains is the same in both modes: a link planted between the check and the mount, or before the daemon restarts a container after a reboot or crash (which never passes the agent), still works. (2) NFS/CIFS volumes pointed at the host's own exports. (3) A future Docker field that confers host reach on an allowed endpoint. (4) Containers created on the host, outside the agent, keep whatever binds they have; the agent refuses getting inside them but still starts, stops and restarts them (its own container excepted). (5) Tagging over an image a running app uses (not the agent's own repository, which is refused): it changes nothing that runs until the app is recreated by an operator. | ACCEPTED with the default (no bind roots) | Default: no bind roots, so (1) needs an operator to opt in. Choose roots no container should write to the top of, and run the agent on the host where apps need host paths (README, "Bind roots and symlinks"); a containerized agent with roots logs a startup warning saying it cannot check them. Review trigger: any new `HostConfig` field or Docker endpoint the dashboard needs. |
| **Browse: a symlink swapped in during a request** | The file browser refuses a path whose directories include a symlink, so `alias -> .ssh` cannot reach a hidden directory. The check is an lstat walk before the operation; a container writing to the same volume could swap a directory for a link between the walk and the use. | ACCEPTED | The `os.Root` still keeps the operation inside that volume, so the most the race reaches is a hidden name in a volume the attacker can already write. `--browse-read-only` removes the mutating routes. |
| **Browse `ReadOnly` now wired** | The `ReadOnly` option (`browse.ReadOnly(true)`) is wired to config (`--browse-read-only` / `EIGHTLY_BROWSE_READ_ONLY`, default off) and applied at the `server.go` browse mount. Production still **defaults mutable** so the file-manager UX (upload/delete/rename) works; the residual is the operator choosing to leave writes enabled. | ACCEPTED (operator/UX trade-off) | All mutations are confined (symlink/traversal) and audited (`browse.mutate`); deployments that don't need writes flip `--browse-read-only` to fail mutations closed with `403`. |
| **A stolen server token is valid until it expires** | `State.Token` lives 30 days. The agent renews it by re-registering from half-life on, but a copy taken before renewal stays valid until its own `exp`; revoking it early is the server's job. | ACCEPTED (bounded lifetime) | Token stored 0600 + uid-gated (protected access list on Windows); bound to one agent's ID; TOFU pin limits which server the token is ever sent to. |
| **TOFU first-contact window** | The first dial to the EOS server captures the pin with no prior anchor — classic trust-on-first-use exposure if an attacker is already MITM at enrollment time. | ACCEPTED (TOFU model) | Optional `--server-ca` adds full chain verification on top of the pin; preseed/pinning docs; first contact is typically on a trusted provisioning network. |
| **Insecure escape hatches exist** (`--insecure-no-auth`, `--insecure-server-tls`) | Operators need a break-glass for local testing / bootstrap. | ACCEPTED | Both are deliberate, loud opt-ins; `--insecure-server-tls` is flag-only (never env-settable); `Validate()` rejects the silent-misconfig path (fail-closed default). |
| **HMAC secret strength is operator-supplied** | The agent verifies tokens with whatever secret it is given; a weak secret weakens A-02. | ACCEPTED (operator responsibility) | Constant-time `hmac.Equal`; fail-closed if no secret; provisioning should generate a high-entropy secret (CSPRNG). |
| **No on-box audit-log integrity chain** | `[SECURITY]` and `browse.mutate` lines are plain zerolog to stdout; a host-root attacker can alter them. | DEFERRED | Logs are greppable and shippable off-box by the operator's log pipeline; an attacker who can edit them already has host root (out of model). |
| **WS exec/attach has no per-session audit record** | The upgrade itself is `[SECURITY]`-gated at auth, but a started exec session isn't separately recorded. | DEFERRED | Auth + CSWSH gate session creation; Docker daemon logs the exec; candidate for parity with `browse.mutate`. |
| **`--allowed-origins` correctness is operator-supplied** | A stale or over-broad allowlist entry would admit an unintended origin. | ACCEPTED (operator config) | Default (empty) is strict same-origin via TLS SNI; absent-Origin still requires a token. |
| **Windows: a file planted before install** | On Windows a local user can create files in a new ProgramData subfolder until the agent locks it down. The agent repairs the access list of a state file, key or certificate it finds there rather than refusing it, so existing installs keep their identity, but it does not check who created the file. | ACCEPTED (install-time window) | `install` creates and protects `C:\ProgramData\eightly-agent` before anything is written; the service protects the data and state folders before it starts; every secret is closed to SYSTEM and Administrators and refused if anyone else keeps access. Reinstall into a fresh folder if one may have been tampered with. |
| **Windows: secrets under ProgramData were readable by local users (fixed)** | Before this fix the data folder, `state.json` (bearer token) and `key.pem` inherited ProgramData's ACL (Users: read), and the documented install put `EIGHTLY_AGENT_SECRET` in a Machine environment variable. Installs from that time should treat the HMAC secret and agent token as exposed to local users. | MITIGATED | Protected DACLs on folder, state, key, cert and secret file; secret read from `--secret-file`; a leftover `EIGHTLY_AGENT_SECRET` alongside the file is refused. Rotate the fleet secret on Windows hosts that ran an older version. |
| **The agent's TLS certificate outlives its validity dates** | The self-signed certificate is issued for a year and never reissued, because Eight.ly OS pins the whole certificate. | ACCEPTED (pinned identity) | Eight.ly OS pins the whole certificate; the agent's healthcheck trusts only that exact certificate and verifies it at a time inside its validity window, so expiry neither breaks the pin nor weakens it. |

## Review triggers

- New `HostConfig` field that affects host reach, or a Docker endpoint the dashboard needs → re-evaluate the proxy allow-list row.
- A deployment that should default to read-only → set `--browse-read-only` / `EIGHTLY_BROWSE_READ_ONLY` (wired).
- Server-side token revocation shipping in Eight.ly OS → revisit the stolen-token row.
- Any new inbound endpoint → re-run `04-stride-per-element.md` for that element.
